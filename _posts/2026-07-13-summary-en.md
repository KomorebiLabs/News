## [DOOMQL: A Full Doom-like Game Engine Built Entirely in SQLite](https://simonwillison.net/2026/Jul/13/doomql/#atom-everything) ⭐️ 8.0/10

Peter Gostev, assisted by GPT-5.6 Sol, created DOOMQL, a project that implements a Doom-like game entirely within SQLite. The system uses SQL for all core mechanics, including movement, collision, combat, and even rendering every pixel on the screen via a recursive CTE ray tracer. This project demonstrates an unconventional and creative use of SQLite, challenging the notion that it is solely a data storage tool. It highlights the potential of SQL for complex procedural logic and real-time rendering, offering a novel perspective for developers interested in creative coding and database capabilities. The game logic and rendering are executed through massive SQL queries, such as a recursive Common Table Expression (CTE) that acts as a ray tracer. Users can interact with the game state using Datasette and its new Apps plugin, allowing for real-time visualization of the database-driven graphics.

rss · Simon Willison · Jul 13, 22:34

**Background**: SQLite is traditionally known as a lightweight, serverless SQL database engine primarily used for local data storage rather than application logic or rendering. Unlike standard relational databases that rely on stored procedures (which SQLite generally lacks), DOOMQL leverages SQL's expressive power for iterative calculations and state management. This approach turns the database into a computational engine, blurring the lines between data persistence and active processing.

## [Critique of Chain of Thought and Rise of Latent Reasoning](https://www.reddit.com/r/MachineLearning/comments/1uviru5/chain_of_thought_is_a_scaling_trap_the_next_wave/) ⭐️ 8.0/10

A recent analysis argues that Chain of Thought (CoT) is becoming a scaling trap due to faithfulness and cost issues, advocating for a shift to latent reasoning methods like Coconut and HRM. It highlights the trade-off between computational efficiency and the loss of interpretability, proposing governance layers to address the 'black box' nature of these new architectures. This perspective challenges the dominant paradigm of explicit textual reasoning, suggesting that future high-performance AI will rely on internal latent states rather than public token generation. Understanding this shift is crucial for developers aiming to build scalable, low-latency systems while managing compliance and auditability requirements in high-stakes domains. Key alternatives include Meta's Coconut, which uses continuous latent representations, and HRM, which mimics the brain's hierarchical processing. The post notes that while these methods improve speed and depth, they require external verification structures like Directed Acyclic Graphs (DAGs) to maintain trustworthiness.

reddit · r/MachineLearning · /u/meowsterpieces · Jul 13, 17:50

**Background**: Chain of Thought (CoT) prompting encourages LLMs to generate intermediate reasoning steps as text, which improves performance on complex tasks but increases latency and token costs. Latent reasoning approaches, such as Coconut and HRM, attempt to perform these computations internally within the model's hidden layers or through recurrent mechanisms, effectively separating the 'thinking' process from the 'speaking' output to enhance efficiency.
